# Handoff record

Use these fields as needed; omit empty sections rather than maintaining boilerplate.

- Task and outcome: what the user requested and the acceptance criteria.
- Stage and authority: research, plan, implementation, or verification; what the user has authorized.
- Code state: repository, branch/revision if available, relevant working changes, and user edits to preserve.
- Decisions: settled choices and material reasons.
- Evidence: relevant file locations, observations, and facts that shaped the implementation.
- Completed: delivered behaviour with relevant files.
- Verification: exact command or interaction, result, and code state tested. Include failures, blocked checks, and skips.
- Remaining: concrete steps in dependency order.
- Open decisions or blockers: missing information and its practical consequence.
- Next action: the first useful step when the work resumes.

Store only what helps another session continue the task. Recheck references and results after code or environment changes.

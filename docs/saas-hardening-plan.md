# SaaS, integrations and accounting — active scope (29 October 2026)

This is an implementation plan and observed-gap record, not a security certification. VA is interpreted as vulnerability assessment; no external target scanning is authorized. User selected vendor-neutral connections; no actual vendor API documentation/credentials are available.

1. **Security and sensitive data:** preserve company/team/role authorization, masking, encrypted credentials, strict cookies, CSRF/origin checks and audit. Close gaps with shared rate limits (not process-local), bounded queries/uploads, secret-safe vendor configuration, webhook authentication/replay defense, retention/deletion, scoped exports, MFA/SSO and tenant-isolation tests. Target [OWASP ASVS](https://asvs.owasp.org/) controls and [OWASP API risks](https://api-security.owasp.org/editions/2023/en/0x11-t10/). Run dependency audit locally, record findings without claiming a pentest; add reproducible dependency/static/DAST steps against owned test environments. AI does not remove the need to validate ordinary authorization and resource-consumption boundaries.
2. **Connections:** vendor definition -> company-owned connection -> versioned credentials/sender/endpoint/header/request and response mapping -> channel-specific effective rates. Show masked credential presence/rotation, connection metadata, JSON request preview, validation results and test-vs-live state. Never put real keys in public definition JSON/audit. Existing encrypted account storage and generic mapping exist; the form and safe credential policy need completion. Real transport is still disabled.
3. **WhatsApp templates:** company + connection/WABA + language + category + immutable content version + external ID. Lifecycle DRAFT/SUBMITTING/PENDING/APPROVED/REJECTED/PAUSED/DISABLED; show reason and status history, submit/status actions, idempotent authenticated callbacks and stale-event checks. Edits require a new registration. Verify approval again at dispatch; internal campaign approval is separate. Simulator status must explicitly say simulated. [Twilio's own BSP guide](https://www.twilio.com/docs/whatsapp/tutorial/message-template-approvals-statuses) documents review and unusable paused/disabled states. Meta documentation currently requires login/rate-limits access; do not invent vendor endpoints.
4. **Paging/filters:** inventory all list endpoints; move paging/filtering to SQL, not browser slicing. Message Explorer already uses keyset paging; bootstrap/provider/rates/template/source/campaign lists still need bounded independent endpoints and filtered selectors. Add date/connection/channel/status/cost-centre filters, bounded exports, matching indexes, and measure representative 10,000/day data before claiming capacity. Aggregations still need period limits/rollups at larger histories.
5. **Vendor console:** logical-message counts separate from attempts; per vendor connection/channel requested/delivered/failed/unknown/queued, failure rate with denominator, last error and investigation links. Rank failures by count and rate; avoid treating low-volume outliers or missing observations as a vendor outage.
6. **Cost-centre detail:** group immutable message budget attribution by cost centre, vendor connection, channel and team. Estimated/reserved/spent/provider usage/invoiced values are distinct. Do not infer historical cost centre from the campaign's editable current definition.
7. **Pricing:** company -> vendor -> connection -> channel -> billing dimension/effective rate version. SMS segment, email recipient/message, WA category/country/chargeable event, platform fee, currency/FX/tax and tier differ by contract. Telegram/Slack/push do not imply universal per-message third-party charges. Extend channel contracts before advertising those as outbound campaign channels. Snapshot billable quantities and unit prices, and reconcile independently of delivery status. Existing runtime supports only email/SMS/WA simulator; no actual provider fees are claimed.

Verification must include access denial across companies/teams, secret non-disclosure, stale WA approval, unapproved-send rejection, pricing snapshots, period boundaries, pagination consistency, ledger non-duplication, and browser workflow evidence. Maintain local handoff/plan and continue over ordinary quota resets; never buy credits/use manual resets. This seven-point request is unfinished until its implementation/tests are recorded.
